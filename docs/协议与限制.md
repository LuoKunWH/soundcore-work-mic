# 协议与限制

这份说明面向想了解实现边界的开发者。日常使用请看根目录的 [README.md](../README.md)。

## 协议从哪里来

帧格式、ECDH/HKDF、AES-CTR 和实时传输布局，是对照 MIT 许可的上游独立写成的 Python：

- 仓库：<https://github.com/tacshi/Soundcore>
- 提交：`d296a1c5c0645797ff7cd3b55e93477a99820857`
- 版权：Copyright (c) 2026 Rocky Shi
- 许可全文：`third_party/licenses/tacshi-Soundcore-MIT-d296a1c.txt`

上游 `PROTOCOL.md` 把完整固件号 `4.92.3.06` 当作示例，不是兼容性证明。设备信息里的固件字段只有 5 个字节。本程序按原样打印这 5 个字节，不会把它换算成完整版本号。已在字段为 `04.92`、手机界面完整版本为 `4.92.3.06` 的设备上解出过 PCM，并成功写到官方 VB-CABLE。这只说明这一类已验证设备可以工作，不表示程序会做版本号换算，也不保证其他固件一定兼容。

<https://github.com/ozil56/SoundcoreForWindows> 的相关提交没有仓库级许可证。这里没有复制它新写的 Python。那里关于其他固件版本的观察，也不能当成这台已验证设备之外的兼容性证明。

因此：握手被拒绝、密钥校验失败、解码失败，程序会停。它不会换一种认证、换一套命令，也不会自己循环重连。手机仍占着连接时，本程序不会解绑。

## 允许发送的命令

| 命令 | 作用 | 约束 |
| --- | --- | --- |
| `01/01` | 读设备信息 | 载荷为空。序列号不保留、不打印 |
| `2E/01` | ECDH 握手 | 只发送本次内存中的 65 字节未压缩 P-256 公钥 |
| `1A/07` | 请求当前录音的实时传输 | 偏移为 0，标志必须为 1。文件号只来自本次收到的 `1A/06`，每收到一次 `1A/06` 最多发一次 |
| `1A/11` | 停止传输 | 载荷只有 `00`。每次 `1A/07` 之后最多发送一次 |

`1A/11` 是停止传输，不是停止设备上的物理录音。随后取消通知并断开 GATT。程序从不发送 `18/82`，所以不会开始、暂停或停止物理录音，也不会发送固件升级、解绑或删除设备录音的命令。

当前文件只认通知 `1A/06`：载荷前 4 字节、小端、大于 0。不发送 `1A/0E` 或 `1B/0E`（它们会带回历史文件列表）。如果连接时设备已经在录音、但不再推送 `1A/06`，请由使用者在设备上先结束后再按一次录音键。程序不会替人发录音停止命令。

托盘桥接会一直等到使用者点「停止桥接」，或出现协议 / 解码错误。它不会因为几秒内还没收到声音就自行退出。在豆上按暂停（或停止）时，设备会发 `1A/0A` 结束本次传输；托盘桥接这时发一次 `1A/11`，但不断开，回到「请按录音键」，等设备再推送 `1A/06` 后重新请求一次实时传输。同一个文件里已经播过的分片序号不会再写进声卡。命令行诊断路径仍可能带有较短的超时，只用于一次性检查。

文件头里的文件号必须和 `1A/06` 一致，错误字节必须为 0，解密结果必须以 `soundcored3200` 开头。分片序号必须连续。任一条件失败即停止。解密后的 Opus 只按 16 kHz、单声道、PCM16 解码，不改采样率重试。

会话密钥只放在内存里。日志和异常不输出密钥、原始通知、序列号或文件号。如使用命令行扫描，本机可能显示蓝牙地址以便选择设备；不要把地址写进议题或对外说明。

## 解码与播放

Windows x64 使用 PyPI 上 PyOgg `0.6.14a1` 官方 wheel 中的 `pyogg/opus.dll`。程序只从已安装的这个 wheel 里加载它，不搜索 `PATH`，也不另外下载 DLL。加载前核对 SHA-256：

`5fa25b62f72f880acf420120d8ca32d31997620cadaab26ae798d13355012d1b`

哈希不一致时，`--check-env` 和实际桥接都会在打开蓝牙之前拒绝继续。

播放使用 sounddevice `0.5.6` 的 Windows x64 wheel（MIT），自带 PortAudio。默认加载不含 ASIO 的 `libportaudio64bit.dll`。如果环境变量 `SD_ENABLE_ASIO` 已设置，程序会拒绝打开声卡。

托盘程序只向名称以 `CABLE Input` 开头的播放端写入 16 kHz PCM16（界面上通常是 `CABLE Input (VB-Audio Virtual Cable)`）。双声道时把单声道复制到左右声道。打开设备时按 WASAPI → MME → DirectSound 的顺序尝试；本机上共享模式 WASAPI 若拒绝 16 kHz，会回退到 MME。程序不打开 `CABLE Output`，也不修改系统默认设备。其他程序应把麦克风选成 `CABLE Output`。

VB-CABLE 本体没有放进本仓库。

## 依赖安装方式

`requirements-windows.txt` 钉死了版本和哈希。`third_party/wheels` 里是对应的官方 wheel，用下面的方式安装，不访问网络，也不升级 pip：

```powershell
.\.venv\Scripts\python.exe -m pip install --require-hashes --no-index --find-links .\third_party\wheels --no-deps -r .\requirements-windows.txt
```

各 wheel 的许可证文本在 `third_party/licenses/`，汇总见仓库根目录的 `THIRD_PARTY_NOTICES.md`。
